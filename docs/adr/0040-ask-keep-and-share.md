# ADR-0040: /ask の回答を「📌 残す」(本人 DM へ保存)・「📢 共有」(確認のうえ共有チャンネルへ公開)できるようにする

- ステータス: proposed
- 日付: 2026-10-07
- 関連: ADR-0034(/ask は本人限定の ephemeral — 本 ADR はその例外を本人の明示操作に限って置く)・
  ADR-0035 D2(interaction 失効時の DM 配送)・ADR-0036 D7(/ask の利用ロール `ask_role_ids`)・
  ADR-0038(Discord 本文検索・質問者の権限での絞り込み)・design.md §4.6(bot.db)・§6.2

## 背景

ADR-0034 で /ask の応答一式を ephemeral(本人限定)にした。その「影響・トレードオフ」に書いたとおり、
ephemeral メッセージは Discord 上に永続せず、**クライアントの再起動やチャンネルの移動で消え、後から参照できない**。
運用では次の 2 つの要望が出ている。

1. 良い回答を手元に残したい(後で読み返す・作業メモにする)。
2. 良い回答をチームに見せたい(同じ疑問を持つ人に役立つ)。ADR-0034 で失われた「他人の Q&A から学ぶ導線」を、
   質問者が選んだ回答に限って取り戻したい。

どちらも本人が明示的に操作した場合に限れば、ADR-0034 の目的(質問の心理的ハードルを下げる = 勝手に公開されない)とは
衝突しない。

## 決定

### D1. 回答メッセージに「📌 残す」「📢 共有」ボタンを置く(質問者本人のみ操作可)

- 回答あり(`answered`)の ephemeral 回答の最終チャンクに、👍👎 と同じ行で並べる。
  customId は `fb:keep:<queryId>` / `fb:share:<queryId>`(確認画面は `fb:share-confirm:` / `fb:share-cancel:`)。
- 押下者を `queries.discord_user_id` と照合し、本人以外は ADR-0034 D3 と同じ文面で拒否する。
  記録の無い queryId は保存・共有しない(本文も本人も確かめられないため)。
- interaction の失効で回答そのものを DM で届けた場合(ADR-0035 D2)は 📌📢 を付けない(👍👎 のみ)。
  DM の回答はそれ自体が残るため。

### D2. 📌 残す = bot.db に保存済みの最終回答を本人へ DM する

- `queries.answer`(出典脚注・stale 注記込みの最終回答)を読み、見出し「📌 /ask の回答(日時 JST)」と
  質問文(本人のもの)を付けて `splitForDiscord` で分割し、本人に DM する。応答は ephemeral で「DM に保存しました」。
- DM を送れない(サーバーメンバーからの DM を拒否している等)ときは、受信設定の変更を ephemeral で案内する。
- DM は本人しか見られないため、ADR-0034 の「本人限定」は保たれる。Discord 引用付きの回答も保存できる。

### D3. 📢 共有 = 確認画面を経て、共有チャンネル(ホームチャンネル = #knowledge_sharing)にだけ投稿する

- 📢 を押すと ephemeral の確認画面「この回答を <#共有チャンネル> に公開します。質問と回答がメンバー全員に見えます。」
  と「公開する / やめる」を出す。押しただけでは投稿しない。
- 「公開する」で、共有チャンネルに「📢 <@質問者> さんの /ask の共有」+ 質問 + 回答(保存済みの最終回答・出典付き)を
  投稿する(2000 字超は分割。公開投稿には 👍👎📌📢 を付けない)。`allowedMentions` は質問者だけを許可し、
  回答本文に含まれる `@everyone`・ロール・他人のメンションは通知しない。投稿後、確認画面を「公開しました」+
  投稿へのリンクに書き換える。
- 投稿先は bot に注入した `shareChannelId` だけ。index.ts は `ops.home_channel_ids` の先頭(ADR-0018 追記 D7)を優先し、
  未設定なら `ops.channel_id` を渡す(本番ではどちらも #knowledge_sharing)。
  未設定なら 📢 を出さない。他のチャンネルには投稿しない。
- **Discord の発言を引用した回答(`sources_json` に `kind: "discord"` を含む)は共有しない。** 📢 を出さず、
  「公開する」が偽造されて届いても拒否する。ADR-0038 の引用は質問者の閲覧権限で絞った本文で、共有チャンネルの
  閲覧者には見えない発言を含みうるため。`sources_json` が読めないときも共有しない(安全側)。

### D4. 共有は 1 回答 1 回まで・記録を残す(`shared_answers`)

- bot.db に `shared_answers(query_id PRIMARY KEY, shared_at, channel_id, message_id, shared_by)` を置く。
  `CREATE TABLE IF NOT EXISTS` で開くたびに作り、`user_version` は消費しない(`inflight_asks` と同じ流儀。
  追加のみ・冪等で、bot.db を共有するホスト側バッチは本表を読まない)。
- 投稿の**前に**主キーで予約し(`message_id` = NULL)、投稿できたら `message_id` を記録する。連打や確認画面の
  二重表示でも投稿は 1 回だけになる。何も投稿できなかったら予約を外して再試行できるようにする。
  先頭チャンクを投稿した後に続きが失敗した場合は、投稿済みとして記録する(二重投稿させない)。
- 2 回目以降は「この回答はすでに共有されています」+ 投稿へのリンクを返す。
- ログは queryId・操作・結果コード・投稿先チャンネル ID・メッセージ ID だけを残し、質問・回答の本文は出さない。
  例外は `safeErrorInfo` で名前とコードだけにする(interaction token を含む URL を残さない)。

## 却下した代替案

- **確認なしで即公開**: 誤タップで質問が全員に見える。ADR-0034 の目的に反する。
- **質問者がチャンネルを選べる**: 閲覧範囲の違うチャンネルへの誤投稿や、閲覧権限の確認が要る。共有先は 1 か所に固定する。
- **Discord 引用を除いて共有する**: 本文の中で引用した内容が残るため、引用を外しても漏れは防げない。
- **共有済みの判定をプロセス内のロックだけで行う**: 再起動を跨いだ二重投稿を防げず、監査記録も残らない。

## 影響・トレードオフ

- 公開した回答には private リポ由来の内容が含まれうる。2026-07-16 の決定で private リポの内容はメンバーに見せてよいが、
  **共有チャンネルの閲覧者に社外メンバーが含まれると、/ask を使えない人(ADR-0036 D7)にも内容が見える**。
  運用者は #knowledge_sharing の閲覧権限を `ops.ask_role_ids` のロールと揃えること(本 ADR はこれを前提にする)。
- 共有は質問者の判断に任せる。回答の正しさは保証されないため、共有投稿にも出典を付けて検証可能にしている。
- 予約の後・投稿の前にプロセスが落ちると、`message_id` が NULL の行が残りその回答は再共有できない
  (「すでに共有されています」になる)。二重公開よりは安全側。必要なら運用者が行を削除する。
- 📌 は DM を許可していない人には使えない(案内を返す)。

## ロールバック

- 📢 だけを止める: `createBot` に `shareChannelId` を渡さない(ボタンが出なくなる)。`ops.home_channel_ids` と
  `ops.channel_id` はそれぞれ /ask の受付・👍 代理マージ(§6.3)と共用のため、設定を外すのではなくコードで外す。
- 全体を戻す: 本変更の revert。`shared_answers` 表は残っても他から読まれないため害はない(必要なら `DROP TABLE`)。
  既に表示中の ephemeral 回答の 📌📢 は押しても反応しなくなる(revert 後のコードは `fb:keep` / `fb:share` を解析しない)。
