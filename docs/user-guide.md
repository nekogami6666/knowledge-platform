# ナレッジ共有 bot 利用ガイド(ユーザー向け)

社内の Discord に住んでいるナレッジ共有 bot(QB Knowledge Ops)の使い方です。
**難しい操作はありません。** 覚えることは実質この 3 つだけです:

| やりたいこと | 操作 |
|---|---|
| 知りたい | `/ask` で質問する |
| 残したい | 💡 を付ける・ボイスチャンネルで話す |
| 承認したい | 👍 を付ける |

書類を書く・整理する・分類する、といった作業はすべて bot(AI)がやります。
人間の仕事は「普通に働くこと」と「AI が作った下書きが正しいか確認すること」です。

---

## 1. 質問する — `/ask`

社内の議事録・ナレッジ・開発リポジトリを横断検索して、**出典リンク付き**で答えてくれます。

1. `#knowledge_sharing` で `/ask` と入力し、質問を書いて送信
   - 例: `/ask 分電盤の配線図はどこ?`
2. bot が資料を探して回答します(30秒〜1分ほど)
3. 回答の下の **👍 / 👎** で評価してください
   - 👍 = 役に立った(bot の成績になります)
   - 👎 = 間違っている・役に立たない → **その質問は自動で「未回答の質問」として記録され、詳しい人に確認が回ります**

**ポイント**: bot は根拠が見つからないときは推測せず「見つかりませんでした」と言います。
これは失敗ではありません — その質問は自動で記録され、後述の「穴埋めの仕組み」(§5)が動き出します。
**答えられない質問こそ、どんどん聞いてください。**

## 2. 会話をナレッジにする — 💡 リアクション

Discord で有益な発言・やり取りを見かけたら、そのメッセージに **💡 リアクション**を付けるだけです。

1. メッセージに 💡 を付ける
2. bot が前後の会話を読んで、ナレッジ記事の下書き(PR)を作ります
   - 雑談や一時的な話は bot が判断して記事にしません(💡 が無視されたように見えたらこのケースです)
3. **あなたに DM** が届きます(下書きへのリンク付き)
4. 内容を確認して、**DM に 👍** を付けるとナレッジとして確定します

💡 を付けてから確定まで、あなたの操作は **2 回**(💡 と 👍)だけです。

## 3. 話してナレッジにする — ボイスチャンネル録音

`🎙 knowledge_memo` ボイスチャンネルは**入室すると自動で録音**されます(退室で終了)。
思いついたこと・引き継ぎたいことを、書かずに話すだけで残せます。

1. `knowledge_memo` VC に入って話す(1人でも複数人でも可)
2. 全員が退室すると録音終了 → bot が文字起こしして記事の下書き PR を作成
3. **最初に入室した人に DM** が届く → 内容確認 → **DM に 👍** で確定

- 長く話しても大丈夫です(裏で自動分割して録音が続きます)
- 録音の音声データは社内サーバーにだけ保存され、一定期間後に自動削除されます(Discord や GitHub には残りません)

## 4. 面談で知識を引き出す — 面談パネル

「この分野は◯◯さんしか知らない」という知識を、面談形式でまとめて記録する仕組みです。
`knowledge_memo` VC の**チャット欄に常設されているパネル**から始めます。

### 面談のやり方(聞き手side)

1. `knowledge_memo` VC のチャット欄を開く(VC にカーソルを当てて 💬 アイコン)
2. パネルの **[🎙 面談を開始]** ボタンを押す
3. **対象者**をメンバー一覧から選ぶ → **テーマ**を一覧から選ぶ(無ければ「✏️ その他」で自由入力)
4. そのまま `knowledge_memo` VC に入って、普通に面談する(質問リストが用意されていれば bot が案内します)
   - 途中でパネルを見ると進行状況(録音中・経過時間)が確認できます
   - 中止したいときはパネルの **[✖ 中止]**
5. 終わったら**全員退室** → 文字起こし全文の PR が作られ、**開始した人に DM** が届く
6. 内容を確認して **DM に 👍** → その夜、AI が面談内容を**複数のナレッジ記事に自動分割**します

コマンドが好きな人は `/interview start` でも同じことができます。

### 面談される側は?

何も操作は要りません。普通に質問に答えて話すだけです。

## 5. 質問に答える — 依頼が来たら返信するだけ

bot が答えられなかった質問や、会議で「未解決」のまま残った疑問は、
毎朝 bot が**その分野に詳しい人**を選んでお願いしに来ます。

```
@あなた さん、◯◯さんが「例の装置の耐圧仕様」を探していました。
1〜2文で教えてもらえますか?このメッセージに返信するだけでOKです。
```

1. **そのメッセージに Discord の「返信」で答える**(1〜2文・話し言葉で OK)
2. bot が ✅ を付けて受領 → あなたの回答をナレッジ記事の形に清書して PR を作ります
3. PR がマージされると、**質問した人に「回答されました」と通知**が届きます

- 文章を整える必要はありません。「たしか 0.6MPa まで。仕様書は棚の青ファイル」くらいで十分です
- 依頼は **1人あたり週3件まで**しか来ません(それ以上は他の人か翌週に回ります)
- 答えられない・自分じゃない、という時は無視しても大丈夫です(7日後に一度だけリマインドが来て、14日で管理側に報告されます)

## 6. ナレッジの鮮度を保つ — 確認 DM に 3 つのボタン

自分が担当(owner)のナレッジは、一定期間ごとに bot から「まだ正しいですか?」と DM が来ます。

| リアクション | 意味 | その後 |
|---|---|---|
| 👍 | 今も正しい | 確認日が更新されるだけ |
| ✏️ | 直したい | 編集用の下書き PR が作られる |
| 🗑 | もう古い | 「古い情報」マークが付く(削除はされません) |

放置しても壊れませんが、古い情報が `/ask` の回答に出続けるので、できれば反応してください。

## 7. ナレッジの確定(承認)— 👍 の意味

この仕組みでは、**AI は勝手にナレッジを確定しません**。必ず人間の 👍 を通ります。

- **自分宛の DM に 👍** → 💡・音声・面談で自分が起点になった下書きの承認
- **`#knowledge_sharing` の通知に 👍** → 毎晩の自動抽出(会議議事録からの一括抽出)の承認。
  通知に「今日のレビュー担当」としてメンションされた人が中心に見ますが、内容が分かる人なら誰が 👍 しても構いません
- 内容を直したいときは、👍 せずに **PR(リンク先)を直接編集**してからマージしても OK です

AI が作る記事には `verification_status: unverified`(未検証)の印が付いています。
👍 は「形式の承認」で、内容の正しさの検証は別途、詳しい人の確認や実測で行う運用です。

## 8. 利用状況を見る — `/stats`

`/ask` の利用件数や 👍👎 の割合を確認できます(自分にだけ表示されます)。

## よくある質問

**Q. 会議で何かする必要はある?**
ありません。議事録が保存されれば、毎晩 AI が自動で「決定・学び・未解決の問い」を抽出して
下書き PR を作ります。人間はレビュー担当がその PR を見て 👍 するだけです。

**Q. AI が間違ったことを書いていたら?**
👍 を押さず、PR を直接編集するか、レビュー担当・管理者に伝えてください。
不確かな情報(「〜かもしれない」「未確認」等)は AI 側でも自動的に「決定」ではなく
「未解決の問い」に回す安全装置が入っていますが、最後の砦は人間のレビューです。

**Q. 機密情報・人事の話はどうなる?**
人事評価・給与・健康・個人のプライバシー・経営機密は、AI が抽出も引用もしないよう
禁止ルールが入っています。万一見かけたら管理者に連絡してください。

**Q. 💡 を付けたのに何も起きない**
見送られた場合は**理由が DM で届きます**(雑談・日程調整など、再利用できる内容が無いと判断された等)。
残したい内容なら、要点を一度メッセージに書き直してから 💡 を付け直すと通ります。
なお **社外秘・顧客案件・契約金額の話でも、結論が出ていない検討中の話でも記録できます**
(bot が見えているチャンネルの内容は残してよい、という運用です。見せたくない情報は
そもそも bot が入っていないチャンネルへ)。ただし API キーやパスワードそのものは記録しません。

**Q. 質問の依頼が来たけど、忙しくて答えられない**
無視して構いません。7日後に一度リマインドが来るだけで、ペナルティはありません。

**Q. 記事はどこに保存されている?**
GitHub の `knowledge-base` リポジトリに Markdown で保存されています。
Discord からリンクをたどればいつでも原文を見られますし、直接編集も PR でできます。
