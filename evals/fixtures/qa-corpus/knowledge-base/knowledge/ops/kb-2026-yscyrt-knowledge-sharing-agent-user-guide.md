## 概要

社内 Discord に常駐するナレッジ共有 bot(表示名 **QB Knowledge Ops**)の、利用者向け操作説明の
**唯一の正典**です。`/ask` で質問する・💡 や VC 録音で残す・👍 で承認する、の 3 つを覚えれば
使えます。書類を書く・整理する・分類する作業は AI がやり、人間の仕事は「普通に働くこと」と
「AI が作った下書きが正しいか確認すること」です。

| やりたいこと | 操作 | 詳しくは |
|---|---|---|
| 知りたい | `/ask` で質問する | §1 |
| 残したい | メッセージに 💡 を付ける / `knowledge_memo` VC で話す / 面談パネル | §2・§3・§4 |
| 承認したい | DM または通知に 👍 を付ける | §7 |

このガイドは knowledge-base リポジトリの `knowledge/ops/` にあり、bot 自身が `/ask` の検索対象に
しています(「bot の使い方」を `/ask` に聞くとこのページが出典になります)。管理者向けの
設定・デプロイ・障害対応は `knowledge-platform` の `docs/admin-guide.md` と `docs/runbooks/` が正典です。

## 1. /ask で質問する(質問・👍👎 評価・見つからないとき)

社内の議事録(dev-minutes)とナレッジ(knowledge-base)を横断検索して、**出典リンク付き**で答えます。

1. `#knowledge_sharing` で `/ask` と入力し、質問を書いて送信(例: `/ask 分電盤の配線図はどこ?`)
2. bot が資料を探して回答します。回答には出典(GitHub / Discord へのリンク)が付きます。
   長い回答は自動で複数メッセージに分割されます。
3. 回答の下の **👍 / 👎** ボタンで評価してください
   - 👍 = 役に立った(bot の成績になります)
   - 👎 = 間違っている・役に立たない → その質問は自動で「未回答の質問」として記録されます

覚えておくこと:

- **根拠が見つからないときは推測せず「根拠が見つからなかったため、推測での回答は控えます」と
  答えます。** これは失敗ではありません。質問は自動で記録され、詳しい人に確認を回す仕組み(§5)の
  燃料になります。答えられない質問こそ、どんどん聞いてください。
- 検索の制限時間は **120 秒**です。超えると「検索がタイムアウトしました」と返るので、質問の対象や
  期間を絞って再度試してください。
- 古い記事が出典のときは、出典行に「※最終確認から時間が経っています(stale)」と注記が付きます。
- 連続で使いすぎると「リクエストが多すぎます」と返ります(目安: 1 人 10 分に 5 回、チャンネル全体で
  10 分に 20 回)。少し待ってから使ってください。
- bot が入っていないチャンネルでは「このチャンネルでは利用できません」と返ります。
- `/stats` で `/ask` の利用件数と 👍👎 の割合を確認できます(どのチャンネルでも可・自分にだけ表示)。

## 2. 💡 リアクションで会話をナレッジにする

bot が見えているチャンネルで有益な発言・やり取りを見かけたら、そのメッセージに **💡 リアクション**を
付けるだけです。あなたの操作は **2 回(💡 と 👍)** で終わります。

1. メッセージに 💡 を付ける
2. bot が前後の会話を読み、ナレッジ記事の下書き(knowledge-base への PR)を作ります。
   PR ができると元メッセージに **✅** が付きます(見送り・失敗のときは **⚠️**)
3. **あなたに DM** が届きます(「💡 をナレッジ化する PR を作成しました」+ PR リンク)
4. 内容を確認して、**その DM に 👍** を付けるとマージされ、ナレッジとして確定します
   (修正したいときは PR を直接編集してからマージ。手順は §8)

見送られる・反応が無いとき:

- 雑談・日程調整など再利用できる内容が無いと判断されると、元メッセージに **⚠️** が付き、
  **見送りの理由が DM で届きます**。残したい内容なら、要点を一度メッセージに書き直してから 💡 を
  付け直すと通ります。
- 画像や添付だけのメッセージはナレッジ化できません(本文があるメッセージに 💡 を付けてください)。
- 💡 は **1 人 1 日 3 件まで**です(超えると「本日の上限に達しています」と DM が届きます)。
- 同じメッセージに 2 人目が 💡 を付けると「この 💡 は既に PR 化されています」と DM が届きます
  (PR は最初の人の DM から承認します)。
- DM を受け取れない設定の人には、元メッセージへの返信で同じ案内が届きます。
- 結論が出ていない検討中の話も記録できます(「決まったこと / まだ決まっていないこと」を分けて、
  確信度 low の記事になります)。機密の扱いは §9 を参照してください。

## 3. VC 録音(knowledge_memo)で話してナレッジにする

`🎙 knowledge_memo` ボイスチャンネルは **入室すると自動で録音**されます(全員が退室すると終了)。
思いついたこと・引き継ぎたいことを、書かずに話すだけで残せます。

1. `knowledge_memo` VC に入って話す(1 人でも複数人でも可。途中参加しても録音は続きます)
2. 全員が退室すると録音終了 → bot が文字起こしして、原本と記事の下書き PR を作ります
3. 録音開始時点の参加者(通常は **最初に入室した人**)に DM が届きます(冒頭の抜粋 + PR リンク)
4. 内容を確認して **DM に 👍** で確定(直したいときは PR を直接編集・§8)

- 長く話しても大丈夫です。**15 分ごとに自動で区切って録音が続きます**(区切りの境目で数秒欠ける
  ことがあるので、大事な発言の途中で切れたら言い直す程度で十分です)。区切りごとに 1 本の PR になります。
- 音声データは社内サーバーにだけ保存され、**14 日で自動削除**されます。Discord や GitHub には
  音声は残りません(残るのは文字起こしと記事だけです)。
- このチャンネルは録音前提です。録音されたくない会話は別の VC で行ってください。

## 4. 面談パネルで知識を引き出す(/interview)

「この分野は◯◯さんしか知らない」という知識を、面談形式でまとめて記録する仕組みです。
`knowledge_memo` VC の**チャット欄に常設されているパネル**(🎙 ナレッジインタビュー)から始めます。

聞き手のやり方:

1. `knowledge_memo` VC のチャット欄を開く(VC にカーソルを当てて 💬 アイコン)
2. パネルの **[🎙 面談を開始]** を押す
3. **対象者**をメンバー一覧から選ぶ → **テーマ**を一覧から選ぶ(一覧は専門性マップから作られます。
   無ければ「✏️ その他(自由入力)」)
4. そのまま `knowledge_memo` VC に入って普通に面談する(対象者×テーマの質問リストが用意されていれば
   bot が案内します)
   - 進行状況(録音中・経過時間)はパネルの **[📋 状況]** で確認できます
   - 中止したいときはパネルの **[✖ 中止]**
   - 開始から **120 分**以内に誰も VC に入らないと自動でキャンセルされます
5. 終わったら**全員退室** → 文字起こし全文の PR が作られ、**開始した人に DM** が届きます
6. 内容を確認して **DM に 👍** → その夜、AI が面談内容を**複数のナレッジ記事に自動分割**します
   (分割結果は通常の抽出 PR としてレビューに回ります・§7)

- コマンドが好きな人は `/interview start`(`person` / `topic` を指定)でも同じことができます。
  `/interview status` で状況、`/interview cancel` で中止です。
- 面談中の録音も 15 分ごとに区切られますが、面談ではすべて 1 本の文字起こしに結合されます。
- 同時に進められる面談は全体で 1 件です。通常の VC 録音が進行中のときも開始できません。
- 面談される側の操作は何もありません。普通に質問に答えて話すだけです。

## 5. 回答依頼に返信する(質問の穴埋め)

bot が答えられなかった質問や、会議で「未解決」のまま残った疑問は、gap-tracker というバッチが
**その分野に詳しい人**を選んで Discord でお願いしに来ます。

```
@あなた さん、◯◯さんが「例の装置の耐圧仕様」を探していました。
1〜2 文で教えてもらえますか? このメッセージに返信するだけで OK です。
(q-2026-xxxxxx)
```

1. **そのメッセージに Discord の「返信」で答える**(1〜2 文・話し言葉で OK。
   「たしか 0.6MPa まで。仕様書は棚の青ファイル」くらいで十分です)
2. bot が **✅** を付けて受領 → 次回のバッチであなたの回答をナレッジ記事の形に清書して PR を作ります
3. PR がマージされると、依頼が投稿されたチャンネルで **質問した人に「回答されました」と通知**されます

- 依頼メッセージ以外への返信は回答として受け取れません(⚠️ と案内が付きます)。必ず bot の依頼
  メッセージに「返信」してください。
- 依頼は **1 人あたり週 3 件まで**しか来ません(それ以上は他の人か翌週に回ります)。
- 答えられない・自分ではない、という時は無視して大丈夫です(7 日後に一度だけリマインドが来て、
  14 日で管理者に報告されるだけで、ペナルティはありません)。
- **現在(2026-08-26 時点)、この依頼の定期配信は管理者判断で停止中です。** 質問の記録と、依頼への
  返信を受け取る仕組みは動いているので、再開時には特別な操作なしにそのまま使えます。

## 6. 鮮度確認の DM(👍 ✏️ 🗑)

自分が担当(`owner`)のナレッジは、記事の種類ごとの期間(手順 90 日・事実/学び 180 日・失敗事例 365 日)
ごとに bot から「🕰️ ナレッジの鮮度確認です」と DM が来ます。**その DM にリアクション**で答えます。

| リアクション | 意味 | その後 |
|---|---|---|
| 👍 | 今も正しい | 確認日(`last_verified`)が今日に更新されるだけ |
| ✏️ | 直したい | 編集用の下書き PR が作られ、リンクが返ってきます。PR 上で内容を直してマージ |
| 🗑 | もう古い | 「古い情報(stale)」マークが付きます(削除はされません。`/ask` では注記付きで引用) |

- 確認の DM は **1 人 1 日 2 件まで**です(確認疲れ対策)。
- **14 日間反応が無いと自動で stale 扱い**になり、管理者に報告されます。壊れはしませんが、
  古い情報が `/ask` の回答に出続けるので、できれば反応してください。
- 記事の frontmatter が壊れているときは「⛔ 処理できません」と返ります(記事を直してから再度リアクション)。

## 7. 👍 による承認 — AI は勝手に確定しない

この仕組みでは、**AI は勝手にナレッジを確定しません**。必ず人間の 👍 を通ります。👍 の場所は 2 つです。

- **自分宛の DM に 👍** → 💡・VC 録音・面談で自分が起点になった下書きの承認。bot が送った DM に
  付けたときだけ有効です。
- **`#knowledge_sharing` の bot 通知に 👍** → 毎晩の自動抽出(会議議事録・面談の文字起こし・開発 PR
  からの一括抽出)の承認。通知に「👀 今回のレビュー担当」としてメンションされた人が中心に見ますが、
  内容が分かる人なら誰が 👍 しても構いません。**bot の通知メッセージ**(PR リンク入り)に付けたときだけ
  有効で、人の投稿に付けても何も起きません(理由が返信で届きます)。

👍 を付けると bot が PR をマージし、「✅ マージしました」と返信します。マージできないときは
理由が返ります:

- 「⛔ マージしません: PR の状態が clean ではありません」 → CI(validate)が赤い、または競合している。
  PR を直してから再度 👍
- 「この PR は既にマージ/クローズされています」 → 何もする必要はありません

内容を直したいときは、👍 せずに **PR を直接編集**してからマージしても OK です(手順は §8)。
AI が作る記事には `verification_status: unverified`(未検証)の印が付いています。👍 は「形式の承認」で、
内容の正しさの検証は別途、詳しい人の確認や実測で行う運用です。

## 8. PR をブラウザだけで修正・削除する(差し戻し)

自動抽出の PR に「これはナレッジではない」「事実が違う」ファイルが混ざっていたら、ローカルに clone
しなくても GitHub のブラウザ画面だけで直せます。**write 以上の権限**を持つ人が対象です(read の人は
PR のコメントで「このファイルは不要」と書いて依頼してください)。

判断の基準:

1. エントリ本文(`## 概要` / `## 事象` / `## 対処 / 学び` 等)が**正確か**。抽出の生成物には誤りが混じりえます
2. `sources` のリンクが実在し、内容を裏づけているか
3. CI(`validate`)が緑か(赤はスキーマ違反。メッセージに従って frontmatter を直す)
4. 問題なければ 👍 またはマージ / 一部だけ不適切なら直接編集 / 全体が不要なら close

ファイルを削除・修正する手順:

1. PR の **Files changed** で、対象ファイル右上の **「…」→「Delete file」**(修正なら「Edit file」)
2. 削除(編集)の下書き画面に遷移します。**この時点ではまだ何も反映されていません。**
   右上の緑 **「Commit changes…」** を押す
3. モーダルで **「Commit directly to the `extract/…` branch」** を選び、**「Commit changes」**。
   ここで初めて PR に反映されます(途中で PR 画面に戻ると下書きは破棄されます)
4. 反映の確認: PR の **Commits タブに自分のコミットが増える** / 削除なら Files changed の件数が 1 減る。
   CI(`validate`)が再実行されるので、緑になってから 👍 でマージ

注意点:

- 複数人が順番に編集して構いません(PR の URL を開けば常に最新。同じファイルを同時に編集するのだけ
  避ける。後から保存した人に「ブランチが更新されました」と出たら、開き直してやり直せば OK)
- **`_meta/state.json` は触らない**(抽出のカーソル。消すと同じ範囲が翌晩また抽出されます)
- **既存ファイルが変更されている**エントリ(PR 本文の「出典追記」「矛盾更新」)は削除ではなく
  「Edit file」で元に戻す。削除すると既存ナレッジごと消えます
- 抽出 PR は **merge または close されるまで次の夜間抽出が止まります**(毎晩「⏸ 見送り」通知が出ます)。
  判断に迷って放置するより、直接編集してマージするか close して流れを止めないでください
- close すると同じ範囲が翌晩もう一度抽出されます(カーソルは merge 時にしか進まないため)。
  「全部いらない」場合も、不要ファイルを消してからマージする方が確実です

## 9. 機密情報の扱い

扱いは入口によって 2 通りです。

- **💡・VC 録音・面談の下書き**: bot が見えているチャンネルの内容は記録してよい、という運用です
  (秘匿はチャンネルの権限で管理されています。見せたくない情報はそもそも bot が入っていないチャンネルへ)。
  社外秘・顧客案件・契約金額の話でも、結論が出ていない検討中の話でも記録できます。ただし
  **API キー・パスワード・トークンなど認証情報の値そのもの**は記録しません。
- **会議議事録・面談文字起こしからの自動抽出(毎晩の extractor)**: 人事評価・処遇・給与・採用候補者の
  個人情報 / 健康・私生活の個人情報 / 経営が機密指定した営業情報(契約金額等)/ 認証情報 /
  個人の能力・適性への評価的言及は、抽出・引用・要約のすべてを禁止しています。

万一すり抜けを見かけたら、その記事を削除する PR を出すか管理者に連絡してください。

## よくある質問

**Q. 会議で何かする必要はある?**
ありません。議事録が保存されれば、毎晩 03:00 に AI が自動で「決定・学び・未解決の問い」を抽出して
下書き PR を作ります。人間はレビュー担当がその PR を見て 👍 するだけです。

**Q. AI が間違ったことを書いていたら?**
👍 を押さず、PR を直接編集するか(§8)、レビュー担当・管理者に伝えてください。「〜かもしれない」
「未確認」のような不確かな表現は AI 側でも「決定」ではなく「未解決の問い」に回す安全装置が
入っていますが、最後の砦は人間のレビューです。

**Q. 記事はどこに保存されている?**
GitHub の `knowledge-base` リポジトリに Markdown で保存されています(`knowledge/<分野>/`・
`decisions/`・`questions/`)。Discord の出典リンクからいつでも原文を見られますし、直接編集も PR でできます。

**Q. 質問の依頼が来たけど、忙しくて答えられない**
無視して構いません。7 日後に一度リマインドが来るだけで、ペナルティはありません。

## 困ったとき

| 症状 | まず確認すること |
|---|---|
| `/ask` が答えない・反応しない | bot がオフライン(メンバーリストでグレー)なら管理者へ。「このチャンネルでは利用できません」なら `#knowledge_sharing` で |
| 💡 を付けても反応しない | 元メッセージに ✅/⚠️ が付いているか。⚠️ なら DM に理由が届いています。何も付かない場合は bot が見えないチャンネルか、bot 停止中 |
| DM が来ない(💡・録音・面談) | DM の受信設定(サーバーメンバーからの DM を許可)。閉じている場合は元メッセージへの返信で案内されます |
| PR を修正・削除したい | §8 の手順(Commit changes… まで押す) |
| 👍 でマージされない | bot の返信の理由を読む(⛔ = CI 赤 or 競合 / 「通知に 👍 でお願いします」= 付ける場所が違う) |
| 上記で解決しない | 管理者に連絡(管理者向けの障害対応は knowledge-platform の `docs/admin-guide.md` §6) |
